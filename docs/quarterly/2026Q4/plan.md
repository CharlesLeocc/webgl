# 2026Q4 季度学习计划：WebGL 与 Three.js

## 季度目标

1. **原生 WebGL：深入掌握着色器和矩阵运算。** 能独立实现模型、视图和投影变换，以及基本的纹理与光照；能解释坐标空间、矩阵乘法顺序和法线变换，并定位由这些概念引起的画面问题。
2. **Three.js：理解渲染逻辑并用测量指导优化。** 能沿固定版本的 `WebGLRenderer` 追踪一次渲染，解释遍历、剔除、排序、程序选择和绘制提交；能为一个场景建立性能基线、提出瓶颈假设并对照验证优化。

两条路线都用原生 HTML 和 JavaScript，在静态 HTTP 服务下运行，不使用 Vite、Vue 或 npm 构建。Three.js 仅作为渲染库，用固定版本的浏览器 ES Module 加载。两条路线各实现一版同一小场景，尽可能保持几何体、相机和场景参数一致，便于对照。

## 12 周路线

周次指学习顺序，不等同于仓库的 `WeekN/` 或日历周。以每周 8～10 小时作为参考节奏，从已有练习做摸底：例如[最小绘制](../../../Week1/Day2/index.html)、[2D 变换矩阵](../../../Week2/Day5/index.html)和[片元着色器特效](../../../Week3/Day5/index.html)。能用已有练习通过验收的内容直接引用；已有成果与本季度新增成果分别记录，不把 2D 实验当作 3D 矩阵能力的证据。

| 周次 | 核心问题 | 实践任务与验收 |
|---|---|---|
| 第 1 周 | GPU 怎样把数据变成画面？ | 从零完成最小 WebGL 绘制；画出 CPU 到屏幕的流程，解释 attribute、uniform、varying 的区别 |
| 第 2 周 | 向量为什么是图形学的基础？ | 用点积实现方向明暗，用叉积计算三角形法线；解释归一化、夹角和坐标基 |
| 第 3 周 | 矩阵到底在变换什么？ | 实现平移、旋转、缩放及组合变换；预测不同乘法顺序的结果，再用画面验证 |
| 第 4 周 | 相机与投影为什么有效？ | 构建可交互的立方体场景；解释视图矩阵、透视投影、裁剪与透视除法 |
| 第 5 周 | 着色器怎样描述表面？ | 实现纹理、漫反射和高光；修复非均匀缩放下的法线错误，解释法线矩阵 |
| 第 6 周 | 怎样从“画物体”走向“处理画面”？ | 实现帧缓冲与一次后处理，并完成程序化动画；解释多 Pass 的数据流与成本 |
| 第 7 周 | Three.js 替我们做了什么？ | 将前面的场景迁移到 Three.js；逐项对应底层概念，并用 `ShaderMaterial` 复现一个效果 |
| 第 8 周 | 一次 Three.js 渲染如何执行？ | 阅读固定版本的 `WebGLRenderer` 关键调用链；标注遍历、剔除、排序、程序缓存及 draw call 的位置 |
| 第 9 周 | 性能问题应该怎样测？ | 构建可调压力场景；使用浏览器 Performance、Spector.js、`renderer.info` 等建立基线并判断瓶颈 |
| 第 10 周 | CPU 与提交开销怎样降低？ | 对比独立 Mesh、共享资源、合并几何体和 `InstancedMesh`；记录 draw call、CPU 耗时及使用限制 |
| 第 11 周 | GPU 与资源开销怎样降低？ | 分别测试分辨率、阴影、透明叠加、材质复杂度、纹理与 LOD；给出效果和成本的取舍依据 |
| 第 12 周 | 能否独立完成闭环？ | 完成综合项目、性能报告和一次现场排错；根据薄弱点进行补练与复测 |

如果季度剩余时间不足，保留完整路线，不把 12 个周次强行压进剩余日历。优先验证矩阵与着色器、Three.js 渲染追踪和至少一组完整的性能对照；季末如实记录未达到的验收点，供下季度决定是否接续。

## 学习方法与阶段验收

每次先提出问题并预测结果，再做一个能隔离变量的最小实验。练习后分别检查：能否不看答案解释原因、独立改写实现、借助工具定位一个故障。引导完成的练习可以作为过程证据，但不等同于通过独立验收。

| 检查点 | 通过标准 | 留存证据 |
|---|---|---|
| 第 4 周：矩阵与相机 | 独立串起模型、视图和投影变换；能画出主要坐标空间，预测两种变换顺序的差异，并定位一个空间或顺序错误。 | 可交互立方体、坐标流程图、预测与实验对照 |
| 第 8 周：Three.js 渲染 | 复现对照场景；依据固定版本源码或帧捕获，说明一个 Mesh 如何进入渲染列表，并追踪到绘制提交。 | 两版场景、版本与调用链笔记、相关源码位置 |
| 第 12 周：综合验收 | 独立完成一次排错；至少有一项优化从瓶颈假设到复测的记录，能解释适用条件和取舍。 | 两个 Demo、优化前后数据、测试条件、结论与未验证项 |

## 进度与性能留证

- 每完成一项，在本季度 `progress.md` 记一行：`完成了什么｜如何验证｜证据链接｜还差什么`。周复盘放 `reviews/`，记录卡点和下一步，不重复抄实验细节。
- 性能实验报告放 `benchmarks/`，关联可运行场景。记录 Three.js 版本、设备和浏览器、视口与 DPR、物体数量等场景参数、预热和采样方式，以及基线和优化后实测数据。对照时尽量一次只改一个变量，保证其余条件相同。
- 将 draw call、CPU 耗时、帧耗时等指标分开写；只测了 draw call 就只报告调用数变化。若比较帧耗时，保留采样统计（如中位数和 P95），不将浏览器帧间隔当作纯 GPU 耗时。实验场景的结果不直接当作业务收益。
