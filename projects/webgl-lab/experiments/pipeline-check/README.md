# 第 1 周：从 JS 数据到屏幕

## 先预测，再运行

设想一个三角形的三个顶点各有颜色，滑块控制整体亮度。先写下两个预测：

1. 把亮度从 `1.0` 调到 `0.5`，三角形的位置、大小、颜色会有哪些变化？改变滑块时需要重新上传顶点吗？
2. 只把顶点颜色传给顶点着色器，没有给内部片元逐一传颜色，那三角形内部的颜色是怎么来的？

## 引导实验：让滑块控制彩色三角形

从仓库根启动静态 HTTP 服务，打开[练习页面](index.html)。比较滑块为 `1.0` 和 `0.5` 时的画面，核对之前的预测。然后对照 [`main.js`](main.js) 追踪一次绘制：

1. `bufferData` 只在初始化时上传一次。两个 attribute 从同一个 `Float32Array` 中分别读取位置和颜色，顶点着色器写入 `gl_Position` 和 `v_color`。
2. 光栅化阶段插值得到每个片元的 `v_color`。片元着色器再把它乘以统一的 `u_brightness`，只改变 RGB，Alpha 保持 `1.0`。
3. 初始化和每次滑块 `input` 都会调用 `render()`。对照这两处入口，解释为什么改亮度不必重传顶点，也不必开动画循环。

## 验收和留证

- **能解释**：不看源码重画数据流，讲清为什么顶点颜色可以形成内部渐变，而 uniform 不是逐顶点数据。
- **能读代码**：指出交错缓冲只上传一次的位置，讲清滑块事件如何通过 uniform 触发重新绘制。这是引导实现，不记作独立写出整个程序。
- **能排错**：先推断把颜色 attribute 的 offset 改为 `0` 会让它读到哪三项，以及顶点位置是否受影响。再对照实现或临时修改验证，记录判断依据。
